# Global Permission and GitHub Access Instructions

- Avoid asking for repeated permission to perform routine development tasks, terminal commands, and GitHub operations.
- Use existing terminal and GitHub access whenever available.
- Perform routine Git commands such as `git status`, `git diff`, `git add`, and `git log` without unnecessary interruptions when permitted.
- For GitHub operations, use the already authenticated GitHub CLI or configured Git credentials when available.
- Avoid unnecessary file renaming, duplicate commands, and repeated approval requests.
- Do not repeatedly request permission for the same safe operation when the tool supports an approved permission scope.
- Before pushing code, review the changes and ensure no secrets, API keys, passwords, or sensitive files are included.
- Never force-push, delete repositories or branches, change repository settings, or overwrite important work without explicit approval.
- If authentication or security approval is required, explain the reason and provide the simplest safe solution.
- Continue working with the available permissions and never bypass security restrictions.
